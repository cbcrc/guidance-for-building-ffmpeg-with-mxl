# Intel Media Tranport Library

[Intel MTL](https://github.com/OpenVisualCloud/Media-Transport-Library) provides a framwork to
handle IP media streams, like ST 2110-20 (and -40), by passing the kernel stack and exposes the
demuxed media data to apps like ffmpeg.

## Get source

This submodule is fork to benefit from the deinterlacing and the audio fix.

```
git submodule update --init
```

## Setup host

Identify the ST 2110 interface name and get its PCI @.

```
sudo ethtool -i enp42s0f0np0  
driver: ice
...
bus-info: 0000:2a:00.0
```

Dpdk requires hugepages:

Create 16GB of hugepages:
```
echo 8192 | sudo tee /sys/kernel/mm/hugepages/hugepages-2097152kB/nr_hugepages
cat /proc/meminfo | grep -i huge

ShmemHugePages:        0 kB
FileHugePages:         0 kB
HugePages_Total:    8192
HugePages_Free:     7707
HugePages_Rsvd:        0
HugePages_Surp:        0
Hugepagesize:       2048 kB
Hugetlb:        16777216 kB
```

### Intel NIC

Install dpdk.

Load VFIO drivers:
```
sudo modprobe vfio
sudo modprobe vfio-pci
```

Find PCI slot
```
/script/nicctl.sh list up
...
2   	0000:2a:00.1	ice         	0   	20    	enp42s0f1np1
...
```

Bind vfio-pci driver to the INTEL NIC:
```
sudo ip link set enp42s0f1np1 down
sudo dpdk-devbind.py -b vfio-pci 0000:2a:00.1
/usr/local/bin/dpdk-devbind.py -s | grep Ethernet
...
0000:2a:00.1 'Ethernet Controller E810-C for QSFP 1592' numa_node=0 drv=vfio-pci unused=
```

Create Virtual functions:
```
/script/nicctl.sh create_vf 0000:2a:00.1
0000:2a:00.1 'Ethernet Controller E810-C for QSFP 1592' numa_node=0 drv=vfio-pci unused=ice
Bind bdf: 0000:2a:00.1 to kernel enp42s0f1np1 succ
Bind 0000:2a:11.0(enp42s0f1v0) to vfio-pci success
Bind 0000:2a:11.1(enp42s0f1v1) to vfio-pci success
...
```

Verify:

1. Dev files created
```
find /dev/vfio 
/dev/vfio
/dev/vfio/213
...
/dev/vfio/218
/dev/vfio/devices
/dev/vfio/devices/vfio0
...
/dev/vfio/devices/vfio5
/dev/vfio/vfio
```

2. Kernel message:
```
dmesg
[1664756.203708] ice 0000:2a:00.1: Enabling 6 VFs
[1664756.306929] pci 0000:2a:11.0: [8086:1889] type 00 class 0x020000 PCIe Endpoint
[1664756.307592] pci 0000:2a:11.0: Adding to iommu group 216
```

3. Get virtual bus

```
dpdk-devbind.py -s | grep -i virtua

```

4. Final Interfaces

## Intel MTL Manager

MTL apps directly open (DPDK) ports but send packet filter through the MTL Manager. Build the image from [IMTL repo](https://github.com/OpenVisualCloud/Media-Transport-Library/blob/main/manager/README.md#run-in-a-docker-container)

Start with privileged mode:
```
docker run --rm -d --name intel-mtl-manager --privileged --net=host -v /var/run/imtl:/var/run/imtl -v /sys/fs/bpf:/sys/fs/bpf intel-mtl-manager:latest
```

On the host, check the socket file is created.
```
ls /var/run/imtl
mtl_manager.sock
```
    
## Build the docker image

Building the image to combine MXL and Intel MTL:

```
docker build -f docker/prod/Dockerfile -t ffmpeg-mxl-imtl .
```

Verify the compiled version:

```
docker run -it --entrypoint /opt/bin/ffmpeg  ffmpeg-mxl-imtl:latest -formats | grep mtl
...
 DEd mtl_st20p       mtl st20p output device
 DEd mtl_st30p       mtl st30p pcm24 output device
```

##  2110 Input to MXL

Define variables

```
LOCAL_IFACE_IP=
VIDEO_MCAST_IP=
PCI_ADDR=
VIDEO_FLOW_ID=
```

Test ffmpeg:

```
docker run -it --rm --net host \
    --devices /dev/vfio \
    --cap-add SYS_NICE \
    -v /var/run/imtl:/var/run/imtl \
    -v /dev/shm/mxl/ffmpeg:/domain \
    --entrypoint /opt/bin/ffmpeg \
    fmpeg-mxl-mtl:latest -pacing_way tsc -interlaced 1 -p_port $PCI_ADDR -p_sip $LOCAL_IFACE_IP -p_rx_ip $VIDEO_MCAST_IP -udp_port 20000 -payload_type 96 -fps 29.97 -pix_fmt yuv422p10le -video_size 1920x1080 -f mtl_st20p -i k -c:v v210 -f mxl -video_flow_id $VIDEO_FLOW_ID /domain
...
```

See the domain on the host in `/dev/shm/mxl/ffmpeg`

Then, check the [docker compose in demo](../demos/st2110_input/compose.yml) with a regular user to benefit from the MediaMTX monitor.

## Test results

Intel MTL lib was tested with the Nvidia/Mellanox but the following observations were made with the Intel NIC. At first glance, the audio-video looks good with no apparent delay nor lip-sync.

### Scaling Limitations

When cores are no longer available, ffmpeg outputs:
```
MTL: 2026-09-23 21:13:50, Error: mt_sch_get_lcore, no available lcore, type lib_sch tried 24
MTL: 2026-09-23 21:13:50, Error: sch_start(0), get lcore fail -5
MTL: 2026-09-23 21:13:50, Error: mt_sch_start_all(0), sch_start fail -5
MTL: 2026-09-23 21:13:50, mt_sch_stop_all, succ
MTL: 2026-09-23 21:13:50, Error: mt_dev_start, start all sch fail -5
MTL: 2026-09-23 21:13:50, Error: _mt_start, mt_dev_start fail -5
```

### Stability

Random crash after few hours, regardless of the source, and their stability (FPGA-based).
