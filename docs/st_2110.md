# Intel Media Tranport Library

[Intel MTL](https://github.com/OpenVisualCloud/Media-Transport-Library) provides a framwork to
handle IP media streams, like ST 2110-20 (and -40), by passing the kernel stack and exposes the
demuxed media data to apps like ffmpeg.

## Get source

```
git submodule update --init
```

## Setup host

Identify the ST 2110 interface name and get its PCI @.

```
sudo ethtool -i enp42s0f0np0  
driver: ice
...
bus-info: 0000:2a:00.0
```

Dpdk requires hugepages:

```
echo 1024 | sudo tee /sys/kernel/mm/hugepages/hugepages-2048kB/nr_hugepages
```

### Intel NIC

Install dpdk.

Load VFIO drivers:
```
sudo modprobe vfio
sudo modprobe vfio-pci
```

Find PCI slot
```
/script/nicctl.sh list up
...
2   	0000:2a:00.1	ice         	0   	20    	enp42s0f1np1
...
```

Bind vfio-pci driver to the INTEL NIC:
```
sudo ip link set enp42s0f1np1 down
sudo dpdk-devbind.py -b vfio-pci 0000:2a:00.1
/usr/local/bin/dpdk-devbind.py -s | grep Ethernet
...
0000:2a:00.1 'Ethernet Controller E810-C for QSFP 1592' numa_node=0 drv=vfio-pci unused=
```

Create Virtual functions:
```
/script/nicctl.sh create_vf 0000:2a:00.1
0000:2a:00.1 'Ethernet Controller E810-C for QSFP 1592' numa_node=0 drv=vfio-pci unused=ice
Bind bdf: 0000:2a:00.1 to kernel enp42s0f1np1 succ
Bind 0000:2a:11.0(enp42s0f1v0) to vfio-pci success
Bind 0000:2a:11.1(enp42s0f1v1) to vfio-pci success
...
```

Verify:

1. Dev files created
```
find /dev/vfio 
/dev/vfio
/dev/vfio/213
...
/dev/vfio/218
/dev/vfio/devices
/dev/vfio/devices/vfio0
...
/dev/vfio/devices/vfio5
/dev/vfio/vfio
```

2. Kernel message:
```
dmesg
[1664756.203708] ice 0000:2a:00.1: Enabling 6 VFs
[1664756.306929] pci 0000:2a:11.0: [8086:1889] type 00 class 0x020000 PCIe Endpoint
[1664756.307592] pci 0000:2a:11.0: Adding to iommu group 216
```

3. Get virtual bus

```
dpdk-devbind.py -s | grep -i virtua
0000:2a:11.0 'Ethernet Adaptive Virtual Function 1889' numa_node=0 drv=vfio-pci unused=
```

4. Final Interfaces
```
ip l
112: enp42s0f1np1: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP mode DEFAULT group default qlen 1000
    link/ether xx:xx:xx:xx:xx:xx rd ff:ff:ff:ff:ff:ff
    vf 0     link/ether xx:xx:xx:xx:xx:xx brd ff:ff:ff:ff:ff:ff, spoof checking on, link-state auto, trust off
    vf 1     link/ether xx:xx:xx:xx:xx:xx brd ff:ff:ff:ff:ff:ff, spoof checking on, link-state auto, trust off
    vf 2     link/ether xx:xx:xx:xx:xx:xx brd ff:ff:ff:ff:ff:ff, spoof checking on, link-state auto, trust off
    vf 3     link/ether xx:xx:xx:xx:xx:xx brd ff:ff:ff:ff:ff:ff, spoof checking on, link-state auto, trust off
```

## Intel MTL manager

This one manages clients.

Start:
```
docker run --rm -d \
  --name intel-mtl-manager \
  --privileged --net=host \
  -v /var/run/imtl:/var/run/imtl \
  -v /sys/fs/bpf:/sys/fs/bpf \
  intel-mtl-manager:latest
```

On the host, check the socket file is created.
```
ls /var/run/imtl
mtl_manager.sock
```

## ffmpeg-mxk-mtl

Build:

```
docker build -f docker/prod/Dockerfile -t ffmpeg-mxl-mtl .
```

Define variables

```
LOCAL_IFACE_IP=
VIDEO_MCAST_IP=
PCI_ADDR=
```

Start:
```
docker run -it --rm --net host --privileged \
    --ulimit memlock=-1 \
    -v /var/run/imtl:/var/run/imtl \
    -v /dev/shm/mxl/ffmpeg:/domain --entrypoint /opt/bin/ffmpeg \
    fmpeg-mxl-mtl:latest -pacing_way tsc -interlaced 1 -p_port $PCI_ADDR -p_sip $LOCAL_IFACE_IP -p_rx_ip $VIDEO_MCAST_IP -udp_port 20000 -payload_type 96 -fps 29.97 -pix_fmt yuv422p10le -video_size 1920x1080 -f mtl_st20p -i k -c:v v210 -f mxl -video_flow_id fe781cad-8a82-4b8e-a3c2-f833c70ac73e /domain
...
```

See the grains on the host

```
find /dev/shm/mxl/ffmpeg
```
