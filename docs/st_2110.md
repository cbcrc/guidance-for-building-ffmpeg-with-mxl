# ST 2110 <-> MXL gateway

[Intel Media Transport Library](https://github.com/OpenVisualCloud/Media-Transport-Library) provides a framework to
handle IP media streams, like ST 2110-20 (-30,-40), by passing the kernel stack (Intel DPDK)
and exposes the demuxed media data to apps like ffmpeg. The same library is also used to produce ST
2110 streams by leverging Mellanox and Intel NICs which can pace packets according to ST 2110-21!
constraints.

ST 2110 <-> MXL would not necessarly require ffmpeg as a wrapper but it definetly provides
flexibility to experiment with  edge cases like (de)interlacing or other conversions, buffering, measurements.

## Setup host

DPDK requires hugepages. Create 16GB of hugepages:

```
echo 8192 | sudo tee /sys/kernel/mm/hugepages/hugepages-2097152kB/nr_hugepages
cat /proc/meminfo | grep -i huge

HugePages_Total:    8192
HugePages_Free:     7707
HugePages_Rsvd:        0
HugePages_Surp:        0
Hugepagesize:       2048 kB
Hugetlb:        16777216 kB
```

On a k3s node, restart the agent to take hugepages into account:
```
sudo systemctl restart k3s-agent.service
```

kubectl describe node <hosntame> | grep -i hugep

```

## Intel NIC

### Rebuild the driver

1. Build the latest and patched 'ice' driver from Intel:

```
cd ./Media-Transport-Library/
grep ICE_VER versions.env
ICE_VER=2.7.6    # <<<<<<<<<<<<<<<<<<<<<<<<< this is the expected version
./script/install_dependencies.sh ice
./script/build_drivers.sh --driver ice
[...]
```

2. Reload ice driver
```
sudo rmmod ice
sudo modeprobe ice
```

3. Verify the new version

```
modinfo ice | grep ^version
version:        2.7.6
[...]
sudo ethtool -i enp42s0f0np0  
driver: ice
version: 2.7.6
...
bus-info: 0000:2a:00.0 # <<<<<<<<<<<<<<<<<<<<<<<<<<<< Identify the ST 2110 interface name and get its PCI @.
```

### Create Virtual functions

One virtual per application. N Rx apps + M Tx apps make N+M VFs.

Intel MTL expects to interact with (virtual) interfaces managed by VFIO-PCI driver.

1. Load it:

```
sudo modprobe vfio
sudo modprobe vfio-pci
```

2. Create Virtual functions.

```
sudo ./Media-Transport-Library/script/nicctl.sh create_vf 0000:2a:00.1 6 # Number of VFs
0000:2a:00.1 'Ethernet Controller E810-C for QSFP 1592' numa_node=0 drv=vfio-pci unused=ice
Bind bdf: 0000:2a:00.1 to kernel enp42s0f1np1 succ
Bind 0000:2a:11.0(enp42s0f1v0) to vfio-pci success
[...]
```

3. Verify in the Kernel messages and new interfaces

```
dmesg
[1664756.203708] ice 0000:2a:00.1: Enabling 6 VFs
[1664756.306929] pci 0000:2a:11.0: [8086:1889] type 00 class 0x020000 PCIe Endpoint
[1664756.307592] pci 0000:2a:11.0: Adding to iommu group 216
[...]
ip l
112: enp42s0f1np1: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP mode DEFAULT group default qlen 1000
    link/ether xx:xx:xx:xx:xx:xx rd ff:ff:ff:ff:ff:ff
    vf 0     link/ether xx:xx:xx:xx:xx:xx brd ff:ff:ff:ff:ff:ff, spoof checking on, link-state auto, trust off
[...]
    vf 6     link/ether xx:xx:xx:xx:xx:xx brd ff:ff:ff:ff:ff:ff, spoof checking on, link-state auto, trust off
```

4. Get virtual PCI address (2 methods):

```
# if you have dpdk installed:
dpdk-devbind.py -s | grep -i virtua
0000:2a:11.0 'Ethernet Adaptive Virtual Function 1889' numa_node=0 drv=vfio-pci unused=
[...]

# if you don't
lspci | grep "Intel.*Virtual"
0000:2a:11.0 [...] # <<<<<<<<<<<<<<<<<<<<<<<<<<<<<<<< this is the PCI @ of the 1st virtual interface
```

## Nvidia/Mellanox NIC

Not suitable for ST 2110 Tx.

0. Stick to Mellanox drivers: `mlx5_core`, `mlx5_ib`, `ib_uverbs`
```
sudo ethtool -i enp42s0f0np0  
driver: mlx5_core
```

1. Create Virtual Functions:
```
echo 8 |sudo tee /sys/class/infiniband/rocep152s0f1/device/sriov_numvfs
```

2. Verify that virtual interfaces are exposed
```
ip l
[...]
ls /dev/infiniband/uverbs*
[...]
# uverbs0 is for the physical iface
```

3. Grab (virtual) PCI addresses
```
lspci | grep "Mellanox.*Virtual"
[...]
```
**The PCI @ format given to Intel MTL must be 0000:XX:XX:XX**

### File Permission

Let the regular user write into the domain and char devices:

```
mkdir -p /dev/shm/mxl/st2110/
chown -R ${UID}:${GID} /dev/shm/mxl/st2110/
chmod -R a+w /dev/vfio/*
chmod -R a+w /dev/infiniband/*
```

## Intel MTL Manager

MTL apps directly open (DPDK) ports but send packet filter through the MTL Manager. Build the image from [IMTL repo](https://github.com/OpenVisualCloud/Media-Transport-Library/blob/main/manager/README.md#run-in-a-docker-container)

Start with privileged mode:
```
docker run --rm -d --name intel-mtl-manager \
    --privileged \
    -v /var/run/imtl:/var/run/imtl \
    -v /sys/fs/bpf:/sys/fs/bpf \
    intel-mtl-manager:latest
```

On the host, check the unix socket is created and let anyone use it.
```
ls /var/run/imtl
mtl_manager.sock
chmod 666  /var/run/imtl/mtl_manager.sock
```

## Test

Define variables

```
LOCAL_IFACE_IP=
RX_VIDEO_MCAST_IP=
RX_PCI_ADDR=
VIDEO_FLOW_ID=
TX_VIDEO_MCAST_IP=
TX_PCI_ADDR=

### ST 2110 -> MXL

```
docker run -it --rm --net host \
    --device=/dev/vfio \
    --device=/dev/infiniband \
    --cap-add SYS_NICE \
    --cap-add NET_ADMIN \
    -v /var/run/imtl:/var/run/imtl \
    -v /dev/shm/mxl/ffmpeg:/domain \
    --entrypoint /opt/bin/ffmpeg \
    ghcr.io/cbcrc/ffmpeg-mxl-imtl:latest -hide_banner -pacing_way tsc -interlaced 1 -p_port $PCI_ADDR -p_sip $LOCAL_IFACE_IP -p_rx_ip $RX_VIDEO_MCAST_IP -udp_port 20000 -payload_type 96 -fps 29.97 -pix_fmt yuv422p10le -video_size 1920x1080 -f mtl_st20p -i k -c:v v210 -f mxl -video_flow_id $VIDEO_FLOW_ID /domain
...
```

See the domain on the host in `/dev/shm/mxl/ffmpeg`

### MXL -> ST 2110

### Multiple sessions:

Example: ST2110->MXL

```
[...]
ffmpeg \
  -hide_banner -pacing_way tsc -interlaced 1 \
  \
  -p_port $PCI_ADDR -p_sip $LOCAL_IFACE_IP -p_rx_ip $RX_VIDEO_MCAST_IP_0 -udp_port 20000 \
  -payload_type 96 -fps 29.97 -pix_fmt yuv422p10le -video_size 1920x1080 \
  -init_retry 20 -f mtl_st20p -i rx0 \
  \
  -p_port $PCI_ADDR -p_sip $LOCAL_IFACE_IP -p_rx_ip $RX_VIDEO_MCAST_IP_1 -udp_port 20000 \
  -payload_type 96 -fps 29.97 -pix_fmt yuv422p10le -video_size 1920x1080 \
  -init_retry 20 -f mtl_st20p -i rx1 \
  \
  -map 0:v:0 -f mtl_st20p -i k -c:v v210 -f mxl -video_flow_id $VIDEO_FLOW_ID_0 /domain \
  -map 1:v:0 -f mtl_st20p -i k -c:v v210 -f mxl -video_flow_id $VIDEO_FLOW_ID_1 /domain 
```

Example: MXL->ST2110

```
ffmpeg \
  -hide_banner -nostats \
  -f mxl -blocking -1 -on_too_late 1 -mxl_read_index_init head -i "mxl:///domain?id=${VIDEO_FLOW_ID_0}" \
  -f mxl -blocking -1 -on_too_late 1 -mxl_read_index_init head -i "mxl:///domain?id=${VIDEO_FLOW_ID_1}" \
  \
  -map 0:v:0 -fps_mode passthrough -pix_fmt yuv422p10le -vcodec rawvideo -pacing_way tsc \
  -p_port $PCI_ADDR -p_sip $LOCAL_IFACE_IP -p_tx_ip $TX_VIDEO_MCAST_IP_0 -udp_port 20000 -payload_type 96 \
  -f mtl_st20p - \
  -map 1:v:0 -fps_mode passthrough -pix_fmt yuv422p10le -vcodec rawvideo -pacing_way tsc \
  -p_port $PCI_ADDR -p_sip $LOCAL_IFACE_IP -p_tx_ip $TX_VIDEO_MCAST_IP_1 -udp_port 20000 -payload_type 96 \
  -f mtl_st20p -
```

Wrapper scripts:

For video only, the container entrypoint `st2110.py` builds such command lines from the environment:
`RX_VIDEO_MCAST_IP` (rx) or `TX_VIDEO_MCAST_IP` (tx) and `VIDEO_FLOW_ID` are space- or
comma-separated lists with the same number of entries, one per session, e.g.:
```
DIRECTION=rx
RX_VIDEO_MCAST_IPs="239.1.1.1 239.1.1.3"
VIDEO_FLOW_IDs="<uuid-0> <uuid-1>"
```

## Test results

### ST 2110 -> MXL

Intel MTL lib was tested with the Nvidia/Mellanox but the following observations were made with the Intel NIC. Based on the monitoring of the domain through MediaMTX, the audio-video looks good with no apparent delay nor lip-sync.

### MXL -> ST 2110

`Rate Limiting` has proven to give narrow video streams in the following conditions:
- Intel E810-C (Mellanox seems to only support tsc (wide))
- interlaced or progressive
- `-fps_mode passthrough`
- 4 simultaneous video streams.
